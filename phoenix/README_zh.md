本仓库包含了 Phoenix 推荐系统的 JAX 示例代码，该系统负责内容的排序（Ranking）和检索（Retrieval）。Phoenix 使用基于 Transformer 的架构来实现**检索**（从数百万个项目中查找相关候选）和**排序**（根据预测的参与度对较小的一组候选进行排序）。

> **注意：** 演示链路里的 Transformer 示例实现是从 xAI 的 [Grok-1 开源版本](https://github.com/xai-org/grok-1) 移植而来的。生产实现见英文 README。

## 概览

Phoenix 是一个预测用户对内容参与度（点赞、转发、回复等）的推荐系统。它分两个阶段运行：

1. **检索 (Retrieval)**：通过近似最近邻（ANN）搜索，高效地将数百万个候选范围缩小到数百个。
2. **排序 (Ranking)**：使用表现力更强的 Transformer 模型对检索到的候选进行打分和排序。

### 检索：双塔模型 (Two-Tower Model)

检索阶段使用**双塔架构**，支持大规模的高效相似度搜索。

#### 检索工作原理

1. **用户塔 (User Tower)**：通过 Transformer 对用户特征和参与历史进行编码，生成归一化的用户嵌入向量 `[B, D]`。
2. **候选塔 (Candidate Tower)**：计算语料库中所有项目的归一化嵌入向量 `[N, D]`。
3. **相似度搜索**：使用点积相似度检索前 K 个候选项目。

---

### 排序：具有候选隔离功能的 Transformer

排序模型使用 Transformer 架构，在推理过程中**候选贴之间无法相互关注**。这是一个关键的设计选择，确保候选贴的得分不取决于批次中存在的其他帖子。

## 关键设计决策

### 1. 基于哈希的嵌入 (Hash-Based Embeddings)

两个模型都使用多个哈希函数进行嵌入查找。

### 2. 共享架构

检索阶段的用户塔使用与排序模型相同的 Transformer 架构。

### 3. 多动作预测 (Multi-Action Prediction)

排序模型同时预测多种参与类型：

```
输出: [B, 候选数量, 动作数量]
                        │
                        ▼
        ┌─────────────────────────────────────┐
        │ 点赞 │ 转发 │ 回复 │ 点击 │ ... │
        └─────────────────────────────────────┘
```

## 运行代码

### 安装

安装 [uv](https://docs.astral.sh/uv/getting-started/installation/)

### 运行排序器 (Ranker)

```shell
uv run scripts/run_ranker.py
```

### 运行检索 (Retrieval)

```shell
uv run scripts/run_retrieval.py
```

### 运行测试

```shell
uv run pytest
```

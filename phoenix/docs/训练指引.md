# Phoenix 推荐系统训练指引

## 📋 概述

本文档详细说明 Phoenix 推荐系统的训练流程，包括：
- **新训练**：从零开始训练模型
- **重训练**：基于已有模型继续训练（增量训练）
- **实时更新**：生产环境的模型更新策略

---

## 📦 前置条件

### 环境准备

```bash
# 安装项目依赖（optax 已包含在主依赖中）
uv sync --dev --group service
```

### 数据准备

训练需要以下数据：

1. **行为日志**：`data/behavior_logs/dt=YYYY-MM-DD/*.parquet`
   - 包含用户与帖子的交互事件
   - 字段：user_id, post_id, author_id, event_time, 19种行为字段

2. **帖子元数据**：`data/post_metadata.parquet`
   - 包含帖子 ID、作者 ID、创建时间、是否在线

3. **训练样本**：`data/training_samples/train_YYYYMMDD.parquet`
   - 由 `data_preprocessor.py` 生成
   - 包含哈希值、历史序列、候选集、标签

**数据预处理流程**（如果已有训练样本可跳过）：

```bash
# 步骤 1：如果有 CSV 格式的原始数据，先转换为 Parquet

  --csv /path/to/your/feed_event.csv \
  --output-dir data/real_data

# 步骤 2：运行数据预处理生成训练样本
uv run data_preprocessor.py \
  --behavior-dir data/real_data/behavior_logs \
  --post-meta data/real_data/post_metadata.parquet \
  --output-dir data/training_samples \
  --date 2024-01-01  # 可选：指定日期
```

## 🚀 第一章：新训练

### 1.1 快速开始（使用模拟数据）

适用于快速验证训练流程，无需真实数据：

```bash
uv run scripts/train_ranker.py --steps 100
```

**说明**：
- 使用模拟数据，不需要准备训练样本
- 训练 100 步，几分钟即可完成
- 输出到默认的 `./checkpoints` 目录

### 1.2 正式训练（使用真实数据）

使用真实的训练样本进行训练：

```bash
uv run scripts/train_ranker.py \
  --data-dir data/training_samples \
  --ckpt-dir checkpoints \
  --steps 5000 \
  --batch-size 4 \
  --lr 1e-4 \
  --log-every 20 \
  --save-every 100
```

**参数说明**：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--data-dir` | `None` | 训练样本目录，不传则使用模拟数据 |
| `--ckpt-dir` | `./checkpoints` | 检查点保存目录 |
| `--steps` | `200` | 训练总步数 |
| `--batch-size` | `4` | 每步 batch 大小 |
| `--lr` | `1e-4` | Adam 学习率 |
| `--log-every` | `20` | 每隔多少步打印一次 loss |
| `--save-every` | `100` | 每隔多少步保存一次检查点 |
| `--streaming` | 关 | 按 Parquet 流式读，内存不随数据集变大 |
| `--resume-params` | 无 | 从此 `.npz` 继续训 |
| `--resume-emb` | 关 | 从 `--ckpt-dir` 加载嵌入表 |

### 1.3 训练输出

训练完成后，`checkpoints` 目录包含：

```
checkpoints/
├── model_params_step100.npz   # 模型参数（每 100 步保存）
├── model_params_step200.npz
├── model_params_step300.npz
├── ...
├── model_params_step5000.npz  # 最终模型参数
└── embedding_tables.npz       # 嵌入表 (user_emb_table, post_emb_table, author_emb_table)
```

**关键文件**：
- `model_params_step*.npz`：Transformer 模型的参数
- `embedding_tables.npz`：三张嵌入表（用户、帖子、作者）

### 1.4 训练监控

训练过程中会输出类似以下日志：

```
step    20 /  5000  loss=0.8234
step    40 /  5000  loss=0.7561
step    60 /  5000  loss=0.7123
...
模型参数已保存到 checkpoints/model_params_step100.npz
嵌入表已保存到 checkpoints/embedding_tables.npz
```

**监控要点**：
- **Loss 下降趋势**：正常情况下 loss 应该逐渐下降
- **收敛速度**：如果 loss 长期不下降，考虑调整学习率
- **训练时间**：首次 step 因 JIT 编译会较慢，后续 step 会加速

## 🔄 第二章：重训练（增量训练）

重训练是指在已有模型基础上继续训练，适用于：
- 添加新数据
- 调整超参数
- 延长训练时间

### 2.1 断点续训

从之前的检查点继续训练：

```bash
uv run scripts/train_ranker.py \
  --data-dir data/training_samples \
  --ckpt-dir checkpoints \
  --resume-params checkpoints/model_params_step500.npz \
  --resume-emb \
  --steps 1000 \
  --batch-size 4 \
  --lr 1e-4
```

**参数说明**：
- `--resume-params`：指定要加载的模型参数文件（只恢复模型参数，不恢复优化器状态）
- `--resume-emb`：从 `ckpt_dir/embedding_tables.npz` 加载嵌入表
- `--steps N`：本次**新增**训练的步数（不是"训练到第 N 步"）

**重要语义**：`train_ranker.py` 不解析 checkpoint 文件名中的步数，`step` 计数器总是从 0 开始、跑满 `--steps` 个新步；优化器状态（Adam 动量）也是全新初始化。因此：

- 原模型训练到 500 步，`--resume-params .../model_params_step500.npz --steps 1000` 的实际效果是**再训练 1000 个新步**，最终 checkpoint 命名为 `model_params_step1000.npz`（文件名反映本次步数，不反映累计步数）。
- 想在原 500 步基础上加练 500 步，应使用 `--steps 500`。

### 2.2 增量训练（添加新数据）

当有新的训练数据时，基于旧模型继续训练：

```bash
# 假设新数据在 data/training_samples_new
uv run scripts/train_ranker.py \
  --data-dir data/training_samples_new \
  --ckpt-dir checkpoints \
  --resume-params checkpoints/model_params_step5000.npz \
  --resume-emb \
  --steps 1000 \
  --batch-size 4 \
  --lr 5e-5  # 使用更小的学习率
```

**注意事项**：
- **学习率调整**：继续训练时建议使用更小的学习率（如 5e-5），避免破坏已学习的特征
- **步数语义**：`--steps` 是本次新增步数（见 2.1 的说明），上例是在 5000 步模型上再训练 1000 个新步
- **数据分布**：确保新数据与原数据分布相似，否则可能需要调整学习率或重新训练
- **灾难性遗忘**：如果新数据与旧数据差异很大，建议重新训练而不是增量训练

### 2.3 超参数调优重训练

不加载参数，从头开始训练，但使用更好的超参数：

```bash
uv run scripts/train_ranker.py \
  --data-dir data/training_samples \
  --ckpt-dir checkpoints_v2 \
  --steps 10000 \
  --batch-size 8 \
  --lr 5e-5
```

**场景**：
- 发现初始学习率过大，模型不收敛
- 增加训练步数以获得更好的效果
- 调整 batch size 以适应显存限制

### 2.4 增量训练常见问题

**Q1：继续训练后 loss 反而上升了？**
- 可能原因：学习率过大，破坏了已学习的特征
- 解决方案：降低学习率（如 1e-5 或 5e-6）

**Q2：新数据训练后模型效果变差？**
- 可能原因：新数据分布与旧数据差异大，导致灾难性遗忘
- 解决方案：重新训练或混合新旧数据

**Q3：如何判断应该继续训练还是重新训练？**
- 继续训练：新数据与旧数据分布相似，只是增加了数据量
- 重新训练：新数据分布差异大，或需要大幅调整模型结构

## ⚡ 第三章：实时更新

实时更新是指在生产环境中持续更新模型，以适应数据分布的变化。本章介绍三种主流方案。

### 3.1 方案对比

| 方案 | 更新延迟 | 训练成本 | 复杂度 | 适用场景 |
|------|----------|----------|--------|----------|
| 定期全量重训练 | 天级别 | 高 | 低 | 数据变化缓慢，追求稳定性 |
| 增量在线学习 | 小时级别 | 中 | 中 | 数据变化较快，需要快速响应 |
| 双塔实时更新 | 秒级别 | 低 | 高 | 召回阶段，需要实时响应 |

### 3.2 方案一：定期全量重训练（推荐用于生产）

**方案概述**：
- 每天或每周用全量数据重新训练模型
- 训练完成后平滑切换到新模型
- 简单可靠，不需要复杂的在线学习基础设施

**实现流程**：

创建每日训练脚本 `scripts/daily_train.sh`：

```bash
#!/bin/bash

# 每日全量训练脚本
# 用法：./scripts/daily_train.sh

set -e

# 配置
DATA_DIR="data/training_samples"
CKPT_BASE_DIR="checkpoints/daily"
STEPS=5000
BATCH_SIZE=16
LR=1e-4

# 获取当前日期
DATE=$(date +%Y%m%d)
CKPT_DIR="${CKPT_BASE_DIR}/${DATE}"

echo "=== 开始每日全量训练 (${DATE}) ==="

# 1. 数据预处理（处理昨天的数据）
YESTERDAY=$(date -d "yesterday" +%Y-%m-%d)
echo "预处理数据：${YESTERDAY}"
uv run data_preprocessor.py \
  --behavior-dir data/behavior_logs \
  --post-meta data/post_metadata.parquet \
  --output-dir data/training_samples \
  --date $YESTERDAY

# 2. 全量重训练（使用所有历史数据）
echo "开始训练..."
uv run scripts/train_ranker.py \
  --data-dir $DATA_DIR \
  --ckpt-dir $CKPT_DIR \
  --steps $STEPS \
  --batch-size $BATCH_SIZE \
  --lr $LR \
  --log-every 50 \
  --save-every 1000

# 3. 模型评估（可选）
# echo "运行模型评估..."
# uv run scripts/evaluate_model.py --ckpt-dir $CKPT_DIR

# 4. 创建生产符号链接
echo "更新生产模型链接..."
LATEST_LINK="${CKPT_BASE_DIR}/latest"
rm -f $LATEST_LINK
ln -s $CKPT_DIR $LATEST_LINK

echo "=== 训练完成 ==="
echo "模型路径: ${CKPT_DIR}"
echo "生产链接: ${LATEST_LINK}"
```

**定时任务配置**（使用 cron）：

```bash
# 编辑 crontab
crontab -e

# 每天凌晨 2 点运行训练
0 2 * * * cd /path/to/phoenix && ./scripts/daily_train.sh >> logs/daily_train.log 2>&1
```

**优点**：
- 简单可靠，不需要复杂的在线学习基础设施
- 可以充分利用最新数据
- 模型质量稳定

**缺点**：
- 更新延迟较高（天级别）
- 训练成本较高

### 3.3 方案二：增量在线学习

**方案概述**：
- 保留在线数据流
- 定期用新数据做增量训练
- 保持模型持续更新

**实现流程**：

创建每小时增量训练脚本 `scripts/hourly_incremental.sh`：

```bash
#!/bin/bash

# 每小时增量训练脚本
# 用法：./scripts/hourly_incremental.sh

set -e

# 配置
HOURLY_DATA_DIR="data/training_samples/hourly"
CKPT_DIR="checkpoints"
STEPS=100
BATCH_SIZE=4
LR=1e-5  # 很小的学习率

# 获取当前小时
HOUR=$(date +%Y%m%d%H)
DATA_PATH="${HOURLY_DATA_DIR}/${HOUR}"

echo "=== 开始每小时增量训练 (${HOUR}) ==="

# 1. 检查是否有新数据
if [ ! -d "$DATA_PATH" ]; then
  echo "没有新数据，跳过训练"
  exit 0
fi

# 2. 增量训练
echo "开始增量训练..."
uv run scripts/train_ranker.py \
  --data-dir $DATA_PATH \
  --ckpt-dir $CKPT_DIR \
  --resume-params ${CKPT_DIR}/model_params_latest.npz \
  --resume-emb \
  --steps $STEPS \
  --batch-size $BATCH_SIZE \
  --lr $LR

# 3. 备份最新检查点
LATEST_STEP=$(ls -t ${CKPT_DIR}/model_params_step*.npz | head -1)
cp $LATEST_STEP ${CKPT_DIR}/model_params_latest.npz

echo "=== 增量训练完成 ==="
```

**定时任务配置**：

```bash
# 每小时的第 10 分钟运行
10 * * * * cd /path/to/phoenix && ./scripts/hourly_incremental.sh >> logs/hourly_train.log 2>&1
```

**优点**：
- 更新延迟低（小时级别）
- 训练成本较低

**缺点**：
- 需要仔细调参避免灾难性遗忘
- 数据分布漂移时模型质量可能下降

### 3.4 方案三：双塔模型实时更新（召回阶段）

对于召回阶段的 `recsys_retrieval_model.py`，可以采用更激进的实时更新策略：

**训练双塔模型**：

```bash
uv run scripts/train_retrieval.py \
  --data-dir data/training_samples \
  --ckpt-dir checkpoints_retrieval \
  --steps 10000
```

**双塔模型的优势**：
1. 用户塔和物品塔可以独立更新
2. 可以只更新新用户/新物品的嵌入
3. 支持在线实时更新嵌入向量

**实时更新嵌入表**（伪代码）：

```python
# 在线服务中实时更新嵌入
def update_user_embedding(user_id, new_behavior_data):
    """实时更新用户嵌入向量"""
    # 1. 哈希用户 ID
    user_hashes = hash_id(user_id)
    
    # 2. 通过用户塔计算新嵌入
    new_embedding = user_tower(new_behavior_data)
    
    # 3. 更新嵌入表
    for idx in user_hashes:
        user_emb_table[idx] = new_embedding

def update_item_embedding(item_id, new_item_data):
    """实时更新物品嵌入向量"""
    # 类似用户嵌入更新
    item_hashes = hash_id(item_id)
    new_embedding = item_tower(new_item_data)
    for idx in item_hashes:
        item_emb_table[idx] = new_embedding
```

### 3.5 生产环境推荐方案

**建议采用"定期全量重训练 + 增量微调"的组合**：

```
每日全量训练（保留最新模型）
  - 使用过去 7-30 天的全量数据
  - 训练 5000-10000 步
  - 保存到 checkpoints/daily_YYYYMMDD/

每小时增量微调（快速响应热点）
  - 使用最近 1 小时的新数据
  - 基于最新全量模型增量训练 100 步
  - 学习率设为 1e-5
  - 保存为 checkpoints/hotfix/

推理服务加载策略：
  - 优先加载 hotfix 模型（如果有）
  - 否则加载最新的 daily 模型
  - 定期回滚验证，确保 hotfix 没有问题
```

**实现脚本** `scripts/combined_update.sh`：

```bash
#!/bin/bash

# 组合更新策略：每日全量 + 每小时增量
# 用法：./scripts/combined_update.sh [daily|hourly]

MODE=${1:-hourly}

if [ "$MODE" = "daily" ]; then
  echo "运行每日全量训练"
  ./scripts/daily_train.sh
elif [ "$MODE" = "hourly" ]; then
  echo "运行每小时增量训练"
  ./scripts/hourly_incremental.sh
else
  echo "用法: $0 [daily|hourly]"
  exit 1
fi
```

## 🔍 第五章：监控与回滚

### 5.1 训练监控

**关键指标**：

1. **训练损失**：应该逐渐下降并收敛
2. **验证损失**：如果验证损失上升，可能过拟合
3. **行为预测概率分布**：应该合理（不会全部接近 0 或 1）
4. **嵌入表变化幅度**：不应该剧烈波动

**监控脚本示例**：

```python
# scripts/monitor_training.py
import numpy as np
import matplotlib.pyplot as plt

def plot_training_loss(log_file):
    """绘制训练 loss 曲线"""
    steps = []
    losses = []
    with open(log_file) as f:
        for line in f:
            if "loss=" in line:
                parts = line.split()
                step = int(parts[1])
                loss = float(parts[4].split('=')[1])
                steps.append(step)
                losses.append(loss)
    
    plt.plot(steps, losses)
    plt.xlabel('Step')
    plt.ylabel('Loss')
    plt.title('Training Loss')
    plt.savefig('training_loss.png')

if __name__ == '__main__':
    plot_training_loss('logs/train.log')
```

### 5.2 异常检测

**异常情况**：

1. **Loss 突然上升**
   - 可能原因：数据质量问题、学习率过大
   - 处理：停止训练，检查数据，降低学习率

2. **Loss 长期不下降**
   - 可能原因：学习率过小、模型容量不足
   - 处理：增大学习率、增加模型层数

3. **预测概率分布异常**
   - 可能原因：标签错误、数据泄露
   - 处理：检查数据预处理逻辑

### 5.3 快速回滚

**回滚流程**：

```bash
# 1. 停止使用新模型
# 通知推理服务停止加载新模型

# 2. 回滚到上一个稳定版本
cp checkpoints/daily_20240422/model_params_step5000.npz \
   checkpoints/production/model_params.npz

cp checkpoints/daily_20240422/embedding_tables.npz \
   checkpoints/production/embedding_tables.npz

# 3. 通知推理服务重新加载
# 重启推理服务或发送重载信号

# 4. 监控回滚后的效果
# 观察关键指标是否恢复正常
```

## 🛠️ 第六章：常见问题

### 6.1 训练相关

**Q1：训练需要多少数据？**
- 至少需要几千个用户的行为数据才能训练出有意义的结果
- 数据越多，模型效果越好
- 建议至少有 10 万条训练样本

**Q2：训练需要多长时间？**
- 使用模拟数据：几分钟
- 使用真实数据：取决于数据量和步数，通常几小时到几天
- 可以通过增加 batch size 或使用 GPU 加速

**Q3：如何选择学习率？**
- 初始训练：1e-4 是一个不错的起点
- 增量训练：使用更小的学习率（5e-5 或 1e-5）
- 如果 loss 不下降：尝试增大学习率
- 如果 loss 震荡：尝试减小学习率

**Q4：如何判断模型是否收敛？**
- 观察 loss 曲线是否趋于平稳
- 验证集 loss 不再下降
- 预测概率分布稳定

### 6.2 重训练相关

**Q5：继续训练后效果变差怎么办？**
- 降低学习率重新训练
- 检查新数据质量
- 考虑重新训练而不是增量训练

**Q6：如何混合新旧数据？**
```bash
# 合并新旧数据目录
mkdir -p data/training_samples_combined
cp data/training_samples_old/*.parquet data/training_samples_combined/
cp data/training_samples_new/*.parquet data/training_samples_combined/

# 使用合并后的数据训练
uv run scripts/train_ranker.py \
  --data-dir data/training_samples_combined \
  --ckpt-dir checkpoints_combined
```

### 6.3 实时更新相关

**Q7：多久更新一次模型比较合适？**
- 数据变化快：每小时更新
- 数据变化慢：每天更新
- 数据很少变化：每周更新

**Q8：如何避免灾难性遗忘？**
- 使用较小的学习率
- 混合新旧数据
- 定期用全量数据重训练

**Q9：如何评估实时更新的效果？**
- 在线 A/B 测试
- 离线评估指标（AUC、NDCG）
- 监控业务指标（CTR、停留时长）

## 1. CLI 参数速查

### 1.1 基础参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--data-dir PATH` | `None` | Parquet 训练数据目录。不传就用模拟数据。 |
| `--ckpt-dir PATH` | `./checkpoints` | 检查点保存目录。 |
| `--steps N` | `200` | 训练总步数。 |
| `--batch-size N` | `4` | 每步 batch 大小。实际训练建议 ≥ 64。 |
| `--lr FLOAT` | `1e-4` | Adam 学习率。 |
| `--log-every N` | `20` | 每 N 步打印一次平均 loss。 |
| `--save-every N` | `100` | 每 N 步保存一次检查点。 |

### 1.2 续训参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--resume-params PATH` | `None` | 从指定路径加载模型参数继续训练。 |
| `--resume-emb` | off | 从 `--ckpt-dir` 加载嵌入表继续训练。 |

### 1.3 数据规模控制

| 参数 | 默认 | 说明 |
|---|---|---|
| `--max-samples N` | `None` | **in-memory 模式**下最多加载 N 行。防 OOM / 快速试跡。streaming 模式下忽略。 |
| `--max-files N` | `None` | 只读目录下排序后前 N 个 Parquet 文件。两种模式都生效。 |

### 1.4 Streaming 模式

| 参数 | 默认 | 说明 |
|---|---|---|
| `--streaming` | off | 流式读取 Parquet，内存占用与数据集大小解耦。**推荐用于全量数据训练。** |
| `--shuffle-buffer N` | `16384` | streaming 模式下的 shuffle buffer 样本数。默认 ≈ 62 MB。 |

### 1.5 Benchmark

| 参数 | 默认 | 说明 |
|---|---|---|
| `--benchmark` | off | 训练循环后额外跑一段稳态 step 计时。 |
| `--warmup-steps N` | `10` | benchmark 热身步数，不计入结果。 |
| `--benchmark-steps N` | `50` | benchmark 计时步数。 |

## 2. 场景模板

### 2.1 日常全量训练

```bash
uv run scripts/train_ranker.py \
  --data-dir data/training_samples \
  --streaming --shuffle-buffer 16384 \
  --batch-size 64 \
  --steps 50000 \
  --log-every 100 \
  --save-every 5000
```

- 内存占用稳定在 ~150 MB 左右；
- 每 5000 步保存一次 `checkpoints/model_params_stepN.npz`；
- 训练完在 `checkpoints/embedding_tables.npz` 写入嵌入表。

### 2.2 快速调试（小数据）

```bash
uv run scripts/train_ranker.py \
  --data-dir data/training_samples \
  --max-samples 20000 \
  --batch-size 64 \
  --steps 200 \
  --log-every 20 \
  --save-every 200
```

- 用 `--max-samples` 限制样本数，避免 OOM；
- 不开 `--streaming`，使用更简单的 in-memory 路径；
- 小步数方便验证 pipeline 跑通。

### 2.3 纯模拟（完全不依赖 Parquet）

```bash
uv run scripts/train_ranker.py \
  --batch-size 64 \
  --steps 1000 \
  --log-every 50 \
  --save-every 500
```

- 对应 `make_simulated_batch_fast`；
- loss 不会真的下降（数据是随机的），适合验证训练循环本身。

### 2.4 只跑 benchmark（不训练）

```bash
uv run scripts/train_ranker.py \
  --steps 0 \
  --batch-size 64 \
  --benchmark \
  --warmup-steps 10 \
  --benchmark-steps 100 \
  --ckpt-dir /tmp/bench
```

- `--steps 0` 跳过训练循环，直接进 benchmark 段；
- 输出类似 `[bench] avg_step=24.15 ms, samples/sec=2650.3 (100 steps after 10 warmup)`。

### 2.5 续训

```bash
uv run scripts/train_ranker.py \
  --data-dir data/training_samples --streaming \
  --batch-size 64 --steps 100000 \
  --resume-params checkpoints/model_params_step50000.npz \
  --resume-emb
```

- `--resume-params` 指向上一次保存的权重；
- `--resume-emb` 让嵌入表也从 `--ckpt-dir` 下的 `embedding_tables.npz` 加载（而不是重新随机初始化）。

## 3. 输出产物

```
<ckpt-dir>/
├── model_params_stepN.npz    # 每 --save-every 步一份
├── model_params_step{total}.npz   # 训练结束的最终权重
└── embedding_tables.npz      # 训练结束时写入（始终是最后一版）
```

推理时加载（参考 `scripts/run_ranker.py`）：

```python
import numpy as np
from scripts.train_ranker import unflatten_dict

raw = np.load("checkpoints/model_params_step50000.npz", allow_pickle=False)
params = unflatten_dict({k: raw[k] for k in raw.files})

tables = np.load("checkpoints/embedding_tables.npz")
user_emb, post_emb, author_emb = (
    tables["user_emb_table"],
    tables["post_emb_table"],
    tables["author_emb_table"],
)
```

## 4. FAQ

### Q1：为什么我跑真实数据时 exit code 是 0，但日志突然断了、训练没跑？

**99% 是 macOS 内核 OOM 静默杀掉了进程**。macOS 在内存不够时会 SIGKILL，Python 进程的 exit code 仍然是 0，给人一种"正常退出"的错觉。

对策：
- 加 `--streaming`；
- 或加 `--max-samples 100000` 等限制；
- 用 `/usr/bin/time -l uv run ...` 观察 `maximum resident set size`。

### Q2：`--streaming` 和 `--max-samples` 能一起用吗？

不能。`--max-samples` **只对 in-memory 路径（不开 `--streaming`）生效**，streaming 模式下会被忽略。

如果想限制 streaming 读的范围，用 `--max-files N` 或直接控制 `--steps`。

### Q3：`--shuffle-buffer` 取多大合适？

经验：

| 数据集规模 | 推荐 shuffle_buffer |
|---|---|
| < 1 M 样本 | 16 k（默认） |
| 1 M – 10 M | 64 k |
| ≥ 10 M | 128 k – 256 k |

越大 → shuffle 质量越好、内存越高；再大收益递减。16 k 已经能覆盖大多数情况，不要盲目开到百万。

### Q4：默认 batch_size=4 是不是太小了？

对，**这是原脚本的默认值，只适合跑通**。实际训练强烈建议 `--batch-size 64` 或以上，step 开销才会被摊薄（见 [04-基准测试与效果.md](./04-基准测试与效果.md) §4.1）。

### Q5：加了 `--benchmark` 之后还会保存 checkpoint 吗？

会。benchmark 段跑在训练循环之后、最终保存之前。产物：
- `model_params_step{training_steps}.npz`（注意：是训练步数，不是 benchmark 步数）
- `embedding_tables.npz`

Benchmark 中更新的权重 **不会** 再被持久化。这是有意的：benchmark 只为计时服务。

### Q6：想切回原来的 in-memory + 全局 shuffle，怎么办？

不加 `--streaming`，配合 `--max-samples` 选一个你内存放得下的行数即可：

```bash
uv run scripts/train_ranker.py \
  --data-dir data/training_samples \
  --max-samples 500000 \    # 50 万行 ≈ 2 GB 内存
  --batch-size 64 --steps 10000
```

### Q7：loss 从头到尾几乎不下降，是 bug 吗？

先检查：
1. 用 **真实数据** 了吗？模拟数据（无 `--data-dir`）本来就是随机标签，loss 不会收敛。
2. `--lr` 是不是太小？默认 `1e-4` 对 Adam 一般 OK，但可以试 `1e-3` 看趋势。
3. 嵌入表没参与更新（是闭包常量）。如果你期望"嵌入也学习"，那当前代码不支持，需要单独改造。

### Q8：跑 `--streaming` 的时候，磁盘 IO 是瓶颈吗？

实测 step 时间 streaming vs in-memory 差 ~6%，说明 IO 没成为瓶颈。如果你把数据放在慢速网络盘或机械硬盘上，差距会拉大。这时可以：
- 把数据软链/拷贝到本地 SSD；
- 或者加大 `--shuffle-buffer`，让每次 buffer 填满时一次性产出更多 batch，摊薄 IO。

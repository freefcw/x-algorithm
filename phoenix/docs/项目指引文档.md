## 📋 项目概述

Phoenix 是一个基于 JAX/Haiku 实现的推荐系统示例项目，源自 xAI 的 Grok-1 开源版本，专门针对推荐系统场景进行了优化。该项目实现了完整的两阶段推荐流水线：**召回（Retrieval）** 和 **排序（Ranking）**，使用 Transformer 架构作为核心组件。

### 🎯 核心特性
- **两阶段架构**：召回 + 排序的完整推荐流水线
- **Transformer 核心**：基于 Grok-1 的 Transformer 架构
- **候选隔离机制**：特殊的注意力掩码确保候选对象评分独立性
- **双塔召回**：支持大规模向量化检索
- **多动作预测**：同时预测多种用户互动行为
- **基于哈希的嵌入**：高效处理大规模 ID 特征

## 📁 文件详细说明

### 1. 核心脚本文件

#### `run_ranker.py` - 精排演示脚本
**功能**：展示推荐系统精排模型的完整推理流程

**主要流程**：
1. **模型配置**：设置嵌入维度、序列长度、哈希配置等参数
2. **初始化推理运行器**：创建 `RecsysInferenceRunner` 实例
3. **生成模拟数据**：创建用户历史和候选集数据
4. **执行推理**：对候选集进行评分排序
5. **结果展示**：显示各候选对象的互动概率预测

**关键参数**：
- `emb_size = 128`：嵌入向量维度
- `history_seq_len = 32`：用户历史最大长度
- `candidate_seq_len = 8`：候选集大小
- `num_actions = 19`：预测的互动行为数量

#### `run_retrieval.py` - 召回演示脚本
**功能**：演示双塔召回模型的大规模检索能力

**主要流程**：
1. **配置召回模型**：复用 Transformer 架构作为用户塔
2. **构建候选池**：生成大规模物品向量库（模拟 1000 个物品）
3. **用户编码**：将用户信息映射为向量表示
4. **相似度检索**：通过点积计算召回 Top-K 候选
5. **结果展示**：显示检索到的物品及相似度分数

**关键特性**：
- 支持离线构建物品向量库
- 在线仅需编码用户向量，效率极高
- 使用 L2 归一化确保点积等同于余弦相似度

### 2. 推理引擎层

#### `runners.py` - 推理运行器核心
**功能**：封装模型推理、参数管理、数据处理等底层逻辑

**核心组件**：

**`BaseModelRunner`**：模型运行器基类

- 提供通用的模型初始化接口

**`ModelRunner`**：精排模型运行器

**`RecsysInferenceRunner`**：精排推理运行器

- 支持 JIT 编译加速推理
- 处理多动作概率输出

**`RetrievalModelRunner`**：召回模型运行器
- 管理双塔模型的参数初始化
- 支持用户塔和候选塔的联合训练

**`RecsysRetrievalInferenceRunner`**：召回推理运行器
- 提供三个核心方法：

### 3. 模型逻辑层

#### `recsys_model.py` - 精排模型实现
**功能**：实现基于 Transformer 的推荐精排模型

**核心架构**：

**`PhoenixModel`**：主模型类
- **输入处理**：将各类特征转换为嵌入表示
- **序列拼接**：构建 `[用户, 历史, 候选]` 的长序列
- **Transformer 处理**：应用特殊的注意力掩码
- **输出解码**：将候选特征投影到多动作概率空间

**关键函数**：

**`block_user_reduce`**：用户嵌入聚合
```python
# 将多个哈希嵌入合并为单一用户表示
user_embedding, user_padding_mask = block_user_reduce(
    user_hashes,           # [B, num_user_hashes]
    user_embeddings,       # [B, num_user_hashes, D]
    num_user_hashes,       # 哈希函数数量
    emb_size,             # 目标维度
)
```

**`block_history_reduce`**：历史嵌入聚合
- 合并推文、作者、行为、场景等多种特征
- 通过线性投影映射到统一维度

**`block_candidate_reduce`**：候选嵌入聚合
- 类似历史处理，但不包含行为特征（候选尚未发生互动）

**`build_inputs`**：构建 Transformer 输入序列
```python
# 序列结构：[用户] + [历史1..S] + [候选1..C]
embeddings = jnp.concatenate([
    user_embeddings, 
    history_embeddings, 
    candidate_embeddings
], axis=1)  # [B, 1+S+C, D]
```

#### `recsys_retrieval_model.py` - 召回模型实现
**功能**：实现双塔架构的召回模型

**核心组件**：

**`CandidateTower`**：物品塔
- 两层 MLP 结构：`[input_dim] → [2*emb_size] → [emb_size]`
- 使用 SiLU 激活函数
- 输出 L2 归一化的向量表示

**`PhoenixRetrievalModel`**：主召回模型
- **用户塔**：使用 Transformer 编码用户历史
- **物品塔**：使用 MLP 编码候选物品
- **检索机制**：通过点积相似度进行 Top-K 召回

**关键方法**：

**`build_user_representation`**：构建用户向量
```python
# 1. 聚合用户及历史特征
# 2. 输入 Transformer 进行时序建模
# 3. Mean Pooling 获得用户表示
# 4. L2 归一化
user_representation, _ = self.build_user_representation(batch, embeddings)
```

**`_retrieve_top_k`**：执行向量检索
```python
# 计算相似度矩阵：[B, D] * [D, N] -> [B, N]
scores = jnp.matmul(user_representation, corpus_embeddings.T)
# 选取 Top-K
top_k_scores, top_k_indices = jax.lax.top_k(scores, top_k)
```

### 4. 基础算子层

#### `grok.py` - Transformer 核心组件
**功能**：提供 Transformer 架构的基础实现，源自 Grok-1

**核心组件**：

**`TransformerConfig`**：架构配置
```python
@dataclass
class TransformerConfig:
    emb_size: int              # 嵌入维度
    key_size: int              # 注意力头维度
    num_q_heads: int           # Query 头数量
    num_kv_heads: int          # Key/Value 头数量（支持 GQA）
    num_layers: int            # 层数
    widening_factor: float     # FFN 扩展因子
    attn_output_multiplier: float  # 注意力输出缩放
```

**`MultiHeadAttention`**：多头注意力
- 支持分组查询注意力（GQA）
- 集成旋转位置嵌入（RoPE）
- 使用 tanh 门控稳定训练

**`RotaryEmbedding`**：旋转位置嵌入
- 实现相对位置编码
- 支持偏移量处理
- 通过旋转变换注入位置信息

**`make_recsys_attn_mask`**：推荐系统专用掩码
**核心创新**：确保候选对象评分独立性
```python
# 掩码规则：
# 1. 用户+历史：全双向注意力
# 2. 候选→用户/历史：允许关注
# 3. 候选→候选：仅自注意力，互不关注
attn_mask = make_recsys_attn_mask(seq_len, candidate_start_offset)
```

**掩码可视化**：
```

    ┌────┼──────┼─────────────────┼───────────────────────┤
    │ U  │  ✓   │  ✓   ✓   ✓   ✓  │  ✗   ✗   ✗   ✗   ✗    │  用户可以关注所有
    ├────┼──────┼─────────────────┼───────────────────────┤
```

## 🧠 算法原理详解

### 1. 两阶段推荐流水线

#### 第一阶段：召回（Retrieval）
**目标**：从百万级候选池中快速筛选出数千个相关物品

**技术方案**：双塔架构
```
用户塔：[用户特征 + 历史行为] → Transformer → Mean Pooling → 用户向量
物品塔：[物品特征 + 作者特征] → MLP → 物品向量
检索：用户向量 · 物品向量 → 相似度排序 → Top-K 召回
```

**优势**：
- 物品向量可离线预计算，支持大规模检索
- 在线仅需计算用户向量，延迟极低
- 向量相似度计算可借助 ANN（近似最近邻）加速

#### 第二阶段：排序（Ranking）
**目标**：对召回的候选集进行精准排序

**技术方案**：候选隔离 Transformer
```
输入序列：[用户] + [历史1..S] + [候选1..C]
处理：Transformer + 特殊注意力掩码
输出：每个候选的多动作概率分布
```

**核心创新**：候选隔离机制
- 候选对象可以关注用户和历史背景
- 候选对象之间无法相互关注
- 确保评分的独立性和一致性

### 2. 基于哈希的嵌入系统

#### 设计动机
推荐系统中存在海量 ID（用户ID、物品ID、作者ID），传统嵌入表会导致参数爆炸。

#### 解决方案：多哈希嵌入
```python
# 每个实体使用多个哈希函数
hash_config = HashConfig(
    num_user_hashes=2,      # 用户特征用2个哈希函数
    num_item_hashes=2,      # 物品特征用2个哈希函数
    num_author_hashes=2,    # 作者特征用2个哈希函数
)

# 嵌入聚合：多个哈希嵌入 → 线性投影 → 单一表示
user_embedding = jnp.dot(
    user_embeddings.reshape(B, 1, num_hashes * D),
    projection_matrix  # [num_hashes * D, D]
)
```

**优势**：
- 大幅减少参数量：从 `O(vocab_size * D)` 降到 `O(hash_table_size * D)`
- 缓解哈希冲突：多个哈希函数提高特征表示鲁棒性
- 支持动态词汇表：新ID无需重新训练嵌入表

### 3. 多动作预测机制

#### 动作类型定义
系统同时预测 19 种用户互动行为：
```python
ACTIONS = [
    "favorite_score",             # 点赞
    "reply_score",                # 回复
    "repost_score",               # 转发
    "photo_expand_score",         # 图片展开
    "click_score",                # 点击
    "profile_click_score",        # 个人资料点击
    "vqv_score",                  # 视频播放质量
    "share_score",                # 分享
    "share_via_dm_score",         # 私信分享
    "share_via_copy_link_score",  # 复制链接分享
    "dwell_score",                # 停留（是否停留超过阈值）
    "quote_score",                # 引用
    "quoted_click_score",         # 引用点击
    "follow_author_score",        # 关注作者
    "not_interested_score",       # 不感兴趣
    "block_author_score",         # 屏蔽作者
    "mute_author_score",          # 静音作者
    "report_score",               # 举报
    "dwell_time",                 # 具体停留时长
]
```

#### 预测流程
```python
# 1. Transformer 输出候选特征 [B, C, D]
candidate_embeddings = transformer_output[:, candidate_start_offset:, :]

# 2. 投影到多动作空间 [B, C, num_actions]
logits = jnp.dot(candidate_embeddings, unembedding_matrix)  # [D, num_actions]

# 3. 转换为概率
probs = jax.nn.sigmoid(logits)  # 每个动作独立预测
```

**应用价值**：
- 支持多目标优化：同时考虑点赞、转发、停留等多种信号
- 个性化推荐：不同用户对不同动作的偏好不同
- 业务灵活性：可根据业务需求调整排序策略

### 4. 旋转位置嵌入（RoPE）

#### 原理
RoPE 通过旋转操作将相对位置信息注入到注意力计算中：

```python
def rotate_half(x):
    """将特征对半拆分并旋转"""
    x1, x2 = jnp.split(x, 2, axis=-1)
    return jnp.concatenate((-x2, x1), axis=-1)

# 旋转公式
x_rotated = x * cos(phase) + rotate_half(x) * sin(phase)
```

#### 优势
- **相对位置感知**：注意力权重依赖于相对位置而非绝对位置
- **外推性好**：可以处理比训练时更长的序列
- **参数高效**：无需额外的位置嵌入参数

```python
def check_gradient_flow(params):
    """检查梯度范数分布"""
    grad_norms = []
    for name, grad in params.items():
        if grad is not None:
            norm = jnp.linalg.norm(grad)
            grad_norms.append((name, norm))
    
    # 按范数排序
    grad_norms.sort(key=lambda x: x[1], reverse=True)
    
    print("梯度范数 Top 10:")
    for name, norm in grad_norms[:10]:
        print(f"{name}: {norm:.6f}")
```

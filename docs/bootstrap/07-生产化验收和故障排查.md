# 07. 生产化验收和故障排查

> **状态：`current-code` + `runbook`**

本篇面向真实部署，不描述已删除的本地 Demo、旧 Phoenix gateway 或随机权重链路。当前生产模型主线是 Phoenix `xrex`；它与 Home Mixer 的请求合同仍需单独适配和验收。

## 1. 上线前置条件

### Home Mixer

- [ ] `MRPYQ_RECOMMENDATION_DATA_ADDR` 指向已验收的业务数据门面；
- [ ] 共享 Redis、UAS 投影和 served-candidates 事件合同已验收；
- [ ] 调用方身份、用户资格、内容权限和可见性判断已验收；
- [ ] `degraded` 规则回退路径有非空率、延迟和错误告警；
- [ ] `production_ready` 的拒绝条件在目标环境得到验证。

### Phoenix xrex

- [ ] Linux、CUDA、xrex native engine 和匹配 checkpoint/index 已准备；
- [ ] ranking 与 retrieval 使用各自的 xrex serving 进程和 readiness；
- [ ] 已完成 xrex serving 合同到 Home Mixer Phoenix 客户端合同的适配；
- [ ] 已完成真实输入、输出 shape、版本 metadata、超时和错误码 contract test；
- [ ] 随机权重和本地 synthetic corpus 不进入生产验收。

### 发布与运维

- [ ] 认证、限流、结构化日志、指标和 trace 已配置；
- [ ] checkpoint、index、代码和数据版本可追溯；
- [ ] 单实例、峰值、超时、重启和多副本行为已压测；
- [ ] 模型故障、依赖故障和数据延迟均有回退与回滚方案；
- [ ] 灰度和停止条件已由业务负责人确认。

## 2. 故障排查顺序

### Home Mixer 无法启动

1. 检查 `HOME_MIXER_MODE` 是否为受支持模式；
2. 检查 `MRPYQ_RECOMMENDATION_DATA_ADDR`、Redis 和 UAS 配置；
3. 查看启动日志中的合同拒绝原因，不要改成已删除的 Demo 模式绕过；
4. 运行 `cargo test -p home-mixer` 和对应 Redis 集成测试。

### Feed 为空

按顺序检查：调用方身份 → 业务召回 → TES 内容补全 → eligibility/VF → 已看状态 → 规则排序 → served 写入。外部服务成功返回但字段缺失，应按合同错误处理，而不是用占位内容填充。

### Phoenix/xrex 不返回结果

1. 确认 Home Mixer 使用的 endpoint 对应 ranking/retrieval 正确服务；
2. 确认协议适配、checkpoint/index 版本和 metadata 一致；
3. 检查输入事件、用户序列和候选 ID 是否能被 xrex 解码；
4. 检查超时、shape、NaN 和版本校验日志；
5. 让 Home Mixer 回退到规则排序，并记录 `phoenix_unavailable`，不要切换到随机权重。

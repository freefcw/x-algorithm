# 06. 分阶段屏蔽和启用策略

> **状态：`current-code` + `design`**

本篇只讨论当前 Home Mixer 的能力开关、生产前置条件和降级边界。旧的本地 Demo 阶段已经删除，不再提供 `HOME_MIXER_MODE=demo`、模拟数据或随机权重链路。

## 1. 当前运行模式

| 模式 | 当前含义 | 生产结论 |
| --- | --- | --- |
| `degraded` | 使用已配置的业务适配器，并允许 Phoenix 不可用时回到规则排序 | 可用于真实规则 Feed 联调；仍需完成业务合同验收 |
| `production_ready` | 启动时检查生产依赖、认证、持久化和模型合同 | 条件未满足会拒绝启动 |

模式解析和启动不变量以 `home-mixer/runtime_config.rs` 为准。未知模式、缺少必需业务地址或违反 fail-closed 约束时，不应通过文档绕过启动检查。

## 2. 开关处置

| 环境变量 | 当前处置 | 启用前置条件 |
| --- | --- | --- |
| `HOME_MIXER_ENABLE_PHOENIX_MOE` | 默认关闭 | xrex/适配层合同、checkpoint、容量和回退测试 |
| `HOME_MIXER_ENABLE_REQUEST_CACHE_SIDE_EFFECT` | 默认关闭 | 存储 schema、幂等、保留和恢复合同 |
| `HOME_MIXER_ENABLE_DEBUG_RPC` | 仅内部调试 | metadata token、权限和审计日志 |
| `HOME_MIXER_ENABLE_VM_RANKER` | 默认关闭 | 当前 proto 与真实 ObjectId 合同完成适配 |
| `HOME_MIXER_ENABLE_AUTHOR_COLD_START` | 默认关闭 | 真实曝光数据、作者资料和离线指标 |
| `HOME_MIXER_ENABLE_COLD_START_THOMPSON_SAMPLING` | 默认关闭 | 冷启动输入和实验指标已验证 |
| `HOME_MIXER_VF_FAILURE_POLICY` | 默认 `fail_closed` | 只有安全负责人确认后才能放宽 |

未签名 cached posts、Demo adapter、整数 Thunder 和本地随机模型不属于当前生产开关。它们已从可执行主线移除，不应重新加入部署配置。

## 3. 推荐启用顺序

```text
代码/协议测试
  → 真实用户、内容、权限和可见性合同
  → Redis 状态与 served-candidates 事件
  → 规则排序 Feed
  → UAS 投影与 Phoenix/xrex contract test
  → 模型灰度、容量测试和回滚
```

每一步必须记录真实地址、输入样本、指标和回退结果。配置了 Phoenix 地址不等于模型已经上线；xrex 与 Home Mixer 当前请求合同未适配前，不能宣称模型路径可用。

## 4. 验收原则

- 禁止使用随机权重、占位正文或 Demo Allow 验证生产质量；
- 模型、索引和特征输入必须来自同一发布版本；
- Phoenix/xrex 不可用时，规则回退必须有明确指标和告警；
- 可见性、删除、拉黑、静音和曝光记录不能通过关闭开关绕过；
- 每次开关变更都要补对应的 contract test 或集成证据。

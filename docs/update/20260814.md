### 1.3 Phoenix relation bool / stale post

提交：`43616cf phoenix: wire relation and stale-post features`

在上游补丁基础上补齐公开快照缺失的合同：

- 公共 `BoolFeature` 固定为 followed、following、stale 三个连续索引。
- 公开 `STALE_POST_14D_TTL_SEC = 1_209_600`。
- 修复上游把 TTL import 错误放进 `recsys_ads_dpa` cfg 的编译问题。
- 旧 parquet 不含 bool 列时保持兼容并全量填 `false`。
- `enable_stale_post` 默认关闭；启用但 bool width 不足时 PyO3 构造直接返回 `ValueError`，避免请求期 panic 或清零计数却不提供 stale 标志。
- 所有 Ranking/Retrieval、SID Retrieval 和 GenRecs server 都只能通过共享 factory 构造；factory 独占 bool width 和 stale 开关，目录级 AST 测试禁止新增 runner 绕过该入口。默认仍为 `false`。
- 在线 candidate 写入 stale；在线 history 和 Arrow history 只写 relation bool。stale/count 清零是候选侧策略，不应用到用户历史。

启用 stale 前还必须让离线候选样本使用同一套“超过 14 天则计数清零并标记 stale”预处理，并重新编译输入签名；当前默认关闭正是为了防止在线/离线候选分布不一致。当前模型只传输这些 post bool tensor，尚未在模型 feature prep 中消费它们；后续让模型使用时需要重新训练/验证 checkpoint。
